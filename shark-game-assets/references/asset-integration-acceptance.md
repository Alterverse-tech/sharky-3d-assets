# 资产接入验收方法论（给验收 Agent 的执行指南）

适用于任意 3D 游戏（跑酷 / 平台 / 射击 / 竞速 / 塔防 / 沙盒 / 俯视 / 第一人称…）把 GLB 模型与动作剪辑接进运行时之后的验收。
目标不是"看起来对"，而是**拿出可证伪的证据**。

## 0. 三条铁律

1. **静默回退是头号敌人。** 成熟的加载器都写了"GLB 失败就用程序化几何体兜底"——于是没接上时画面照样正常、控制台照样干净。**默认假设"没接上"，直到拿出证据。**
2. **像素会骗人，数字不会。** 画布留的是最后一帧；进程死了画面也还在。凡是"动没动/对没对"，一律采样两次数值比对。
3. **数学自洽 ≠ 视觉正确。** 用同一个未经独立验证的常量既做实现输入又做测试基准，测试必然通过——这是假阳性，不是验收。

---

## 1. 先分类：决定这份资产要过哪几关

不同资产查的东西不同。先从 manifest 与游戏代码确定三件事，再照表执行。

| 维度 | 取值 | 影响 |
|---|---|---|
| **资产类别** | 角色/生物（有骨骼）、载具、道具、可拾取物、环境件 | 决定 A 关取证方式、B 关定向方法 |
| **定向模型** | 速度驱动转向 / 路径跟随 / 朝向玩家 / 固定朝向 / 无方向（球形对称） | 无方向者跳过 B 关并在报告中写明 |
| **支撑模型** | 落地站立 / 悬浮（声明离地高度）/ 飞行（无地面约束）/ 挂载（父节点决定）/ 轮式接地 | 决定 D 关的支撑判据 |

游戏的**规范前向轴**（canonical forward）由游戏自己声明，不存在通用默认值——先从代码读出来（移动矢量朝哪、相机看向哪），写进报告，后续所有朝向结论都相对它表述。

---

## A 关：真的用上 GLB 了吗（所有资产必查）

**有骨骼的资产**：运行时可视对象里必须存在蒙皮网格与骨骼。

```js
let skinned = null, bones = 0, meshes = 0;
visualRoot.traverse(o => {
  if (o.isSkinnedMesh && !skinned) skinned = o;
  if (o.isBone) bones++;
  if (o.isMesh) meshes++;
});
```
通过：`skinned` 存在且 `bones > 0`，骨骼为解剖学命名而非 `Node001`。

**无骨骼资产（道具/载具/环境）**：程序化回退通常是少量基础几何体，真实 GLB 通常网格/材质/顶点数明显更多。取证组合拳：
- 顶点总数与材质数远超回退实现（回退往往 < 10 个 mesh、无贴图）
- 场景图里存在导出器留下的命名（`tripo_node_*`、`Sketchfab_model` 等）
- 网络请求 `.glb` 返回 200，文件头前四字节 `676c5446`（`glTF`），字节数与 manifest `sizeBytes` 一致
- 内容哈希与 manifest `sha256` 一致（最强证据）

**多资产/整表验收**：遍历 `manifest.assets`，逐条确认它**确实被某个游戏槽位取用**。常见事故是 manifest 里有 8 个资产、代码只绑了 1 个，其余静默闲置。报告须列出"已接入 / 已下载未使用 / 加载失败"三档。

❌ 不可接受的"证据"：控制台打印了一行"已接入"。日志可能位于 try 块内、先于失败打印。

---

## B 关：朝向与运动方向一致吗（仅方向敏感资产）

### 禁止的推断方式
- 引擎/格式惯例（"glTF 都朝 +Z"）——不成立。
- 只看包围盒最宽轴——它只给出**轴**，给不出**方向**（`+X` 与 `−X` 都满足）。
- 生成时的 prompt、文件名、别的资产的经验值。

### 定向方法（按可靠度排序，取到即可，存疑则叠加）

1. **可信元数据**：资产自带经审计的 orientation 字段。
2. **命名关节 + 手性定则**（人形/四足等有语义骨骼者）
   ```
   LEFT    = normalize(左侧关节.worldPos − 右侧关节.worldPos)
   FORWARD = LEFT × UP            // 右手系，UP 取游戏的上轴
   ```
   用**两组独立关节**互证（如大腿组 + 手部组）；结论不一致则降级到方法 3/4。
3. **几何特征**：面部/驾驶舱/车头灯/枪口/推进器/尾翼等单向特征相对质心的方位；轮式载具用轮轴排布判轴、车头造型判向。
4. **多角度渲染判读**：在纯背景转台上按 45° 步进渲染并标注偏航角，肉眼确认哪一面是正面（本 skill 提供 `/regeneration.html?audit=<assetId>` 与 `record-orientation.mjs`）。
5. **临时轴标**：游戏内挂调试箭头。

### 必须用完整 TRS 矩阵
父节点常带 −90° 旋转（Z-up → Y-up 转换）。**只累加 translation 求世界坐标会得到彻底错误的结果。**
自检信号：解算后若出现"头低于手""脚不在最低处""所有关节落在同一平面"，说明忽略了旋转，结果作废重算。

### 渲染验收（不可跳过，按视角选做法）
| 视角 | 通过判据 |
|---|---|
| 第三人称追尾 | 前进时看到背面；转动相机后前进，朝向随之改变 |
| 俯视/等距 | 移动矢量与模型正面在俯视投影上同向 |
| 侧视卷轴 | 向右移动时角色面朝右，反向立即翻面 |
| 第一人称 | 检查手臂/武器模型与准心朝向一致 |
| 固定朝向摆件 | 正面朝向设计意图的观察位 |

要求：面部/单向特征、运动速度矢量、正在播的位移类动画，三者方向一致。截图留证。

### 数学覆盖
把审计得到的原生前向做完整变换后，与**实际水平速度**逐向点积：
```
worldForward = nativeForward.applyQuaternion(visual.q).applyQuaternion(root.q).normalize()
assert(worldForward.dot(velocity.setY(0).normalize()) >= 0.95)
```
覆盖前后左右 + 四个斜向共八向。**期望值必须来自审计或独立渲染，不得复用实现里的同一常量**，否则只证明了自洽。

### 记账与失效
写入 manifest `orientation`：`nativeForwardAxis` / `canonicalForwardAxis` / `calibrationYawDegrees` / `auditMethod` / `auditEvidence`（写下实测数值）/ `sourceHash` / `status`。
**GLB 内容哈希变化即作废重审**——重新生成、重绑骨、换网格、改导出轴都算，即使 id 与文件名没变。

### 结论分级（如实使用，不得跃级）
| 级别 | 含义 |
|---|---|
| `UNVERIFIED` | 未独立确定原生前向 |
| `AXIS_AUDITED` | 已从资产几何/骨骼确定前向轴 |
| `MATH_VERIFIED` | 已审计轴 + 八向点积全过 |
| `VISUALLY_VERIFIED` | 渲染检查通过，数学覆盖不全 |
| `ACCEPTED` | 两者都过 |

渲染无法验证时如实写"数学验证已过，渲染验收待办"，**禁止**报"朝向通过"。

## C 关：动画在播吗、与驱动量匹配吗

1. **在播**：间隔采样同一节点（骨骼或机械部件）的世界矩阵，数值必须变化。不变 = 没播（常见于 clip 未绑上骨架、mixer 未 update、clip 名不匹配）。
2. **绑得上**：动作 GLB 常为**纯动画无网格**，其 scene 不得加入场景，只能作为 clip 源挂到基础模型的 mixer。绑定失败必须显式降级并说明，**不得把程序化/回退动画说成 retarget 剪辑**。
3. **匹配驱动量**：播放速率要挂在真实驱动量上，否则出现"原地滑步"类失配。
   - 位移动画 ↔ 移动速度；轮子/螺旋桨/齿轮 ↔ 转速；波浪/呼吸 ↔ 时间；攻击 ↔ 攻速。
   - 验收：取两个不同驱动量下的周期，比值应随驱动量单调变化。
4. **状态机完整**：每个游戏状态都有对应视觉表现，切换有过渡不闪跳；无对应剪辑时的回退姿态是有意设计的，不是穿模。
5. **作用分层**：资产校准旋转在**视觉子节点**，玩法旋转/位移在**gameplay 根节点**，碰撞体不随视觉动画缩放。混在一层叠加是常见错误源。

---

## D 关：空间落位（按支撑模型判定）

先量包围盒：水平居中、高度/尺寸等于配置目标值、朝向校准后仍居中。再按支撑模型查支撑点：

| 支撑模型 | 判据 |
|---|---|
| 落地站立 | 最低点 ≈ 地面高度（0），不陷入、不悬空 |
| 轮式接地 | 轮子最低点 ≈ 0（车身底盘允许离地） |
| 悬浮 | 最低点 ≈ 声明的离地高度，浮动幅度不穿地也不脱离可交互高度 |
| 飞行 | 无地面约束，但需符合声明的高度带；不得穿越地形 |
| 挂载/子物体 | 相对父节点锚点正确，父节点移动时不脱节 |

**关键陷阱**：`Box3.setFromObject` 对蒙皮网格量的是**绑定姿势**，不是当前动画姿势。
曾出现包围盒报告"脚在 0、高度正确"，画面里角色却陷进地面半截。
→ **落位必须量运行时节点世界坐标**，不能只信包围盒：

```
{ Hip: 0.00, L_Foot: -0.485, R_Foot: -0.769 }   // ❌ 髋部被压到 0，双脚在地面以下
{ Hip: 0.92, L_Foot: 0.377, R_Foot: 0.198 }     // ✅ 修正后
```

已知成因之一：重定向导出把根/髋部位置轨道写成 0。修法是按绑定姿势**逐轴**重定基准——骨架局部空间可能是 Z-up，**不要假设高度在 Y 轴**；保留剪辑自身起伏，只补回被抹掉的站立高度；且必须在 mixer 首次播放**之前**读取绑定姿势。

**碰撞与视觉分离**：碰撞体取稳定的玩法尺寸，不取原始模型包围盒。验收要确认换模型后玩法判定没跟着漂移。

---

## E 关：回退路径仍然可用

故意让 GLB 加载失败（改错 URL、断网、删文件），游戏**必须仍可玩**，且日志明确说明启用了程序化回退。
验收报告必须区分"本次跑的是 GLB 还是回退"——否则一份"全绿"报告可能整篇都在验收回退实现。

---

## F 关：性能没有被资产拖垮

接入前后对比：帧时间、draw call、三角面数、内存/纹理占用。
判据：目标机型仍达标（如 60fps）；同类实体走实例化或共享几何体；无逐帧 `new`/材质重建。
资产接入常见退化：每个实例克隆整套材质、贴图未复用、骨骼数超预算。

---

## 报告格式

逐关给出：判据 → 实测数值 → 结论。数值必须是真实采样值，不得概括为"正常"。

```
资产   player / character / 速度驱动转向 / 落地站立     规范前向 = -Z
A 接入  ✅ SkinnedMesh 存在，41 骨骼（Hip/L_Thigh/R_Hand…），GLB 200，sha256 与 manifest 一致
B 朝向  ✅ ACCEPTED  原生 +X（大腿组 dot 0.996，手部组一致），校准 +90°，追尾镜头见背影
C 动画  ✅ 骨骼世界坐标随时间变化；clip 绑定成功；播放速率随移动速度单调上升
D 落位  ✅ 髋部 0.92 / 脚踝 0.20 / 包围盒 min.y=0 / 高 1.80
E 回退  ✅ 断链后程序化模型接管，游戏可玩
F 性能  ✅ 96 draw call，稳定 60fps
整表    8 个资产：6 已接入 / 1 已下载未使用 / 1 加载失败（已回退）
```

## 反模式清单（出现即判不通过）

- 用"控制台没报错"当作接入成功的证据
- 用引擎惯例、文件名或 prompt 假定前向轴
- 只用包围盒判断落位；对蒙皮网格不查运行时姿势
- 忽略四元数、只累加平移求世界坐标
- 数学测试的期望值与实现取自同一未验证常量
- 把绑定失败的剪辑说成"正在播放 retarget 动画"
- 朝向未做渲染检查却报 `ACCEPTED`
- 只验收 manifest 里的第一个资产，其余默认同理
- 报告写"表现正常"而不给实测数值
